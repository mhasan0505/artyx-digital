# Artyx Digital Website Blueprint & Implementation Specifications

**Strategy:** Premium digital agency + business software products  
**Markets:** Bangladesh and international  
**Business priority:** Balanced — agency services and owned products  
**Positioning concept:** Build Better. Operate Smarter. Grow Faster.

---

## 1. Strategic direction

### 1.1 Brand positioning

Artyx Digital should be presented as a technology and digital growth partner that helps businesses establish a stronger online presence, improve operations and acquire more customers.

**Primary positioning statement**

> Artyx Digital helps ambitious businesses build better digital experiences, operate smarter with technology and grow through digital marketing.

**Primary tagline**

> Build Better. Operate Smarter. Grow Faster.

**Supporting message**

> From high-performing websites and custom software to business management systems and digital growth, we bring the technology and expertise businesses need to move forward.

### 1.2 Three business pillars

| Pillar | What it includes | Primary audience |
|---|---|---|
| Digital Experiences | Websites, e-commerce, web applications, branding | Startups, SMEs, established businesses |
| Business Technology | Custom software, POS, OMS | Retailers, online sellers, growing businesses |
| Digital Growth | SEO, paid advertising, content, digital strategy | Businesses seeking visibility and leads |

The three pillars should have equal strategic importance on the homepage. Individual campaigns can prioritize one pillar at a time.

### 1.3 Audience and market strategy

**Bangladesh**
- Retail and electronics shops.
- Facebook and Instagram commerce sellers.
- Restaurants and service businesses.
- SMEs needing websites, software or marketing.
- Growing businesses looking to automate operations.

**International**
- Startups and small-to-medium businesses.
- Founders seeking web development or SaaS development.
- Companies needing custom software and digital transformation.
- Businesses looking for outsourced development or marketing support.

Do not create a separate international brand identity. Use one consistent brand, with market-specific landing pages, proof, messaging and contact options where needed.

### 1.4 Core conversion goals

Every important page should guide visitors toward one of these actions:

1. Start a project.
2. Book a POS demo.
3. Request an OMS demo.
4. Request a marketing audit.
5. Contact the team.

Avoid using the same generic contact CTA for every visitor. Match the CTA to the page's purpose.

# 4. Premium visual design system

## 4.1 Design direction

**Design concept:** Premium modern technology company.

The site should feel:
- Confident.
- Modern.
- Precise.
- Business-focused.
- Technically capable.
- Internationally credible.

Retain the strongest aspects of the existing visual identity, but improve consistency, typography, spacing, image quality and conversion hierarchy.

## 4.2 Suggested visual palette

Use the following as a starting point, then validate against the existing logo and brand assets.

| Role | Suggested color |
|---|---|
| Primary background | Deep navy `#0B1020` |
| Secondary background | `#121A2D` |
| Main accent | Electric blue `#4D7CFE` |
| Secondary accent | Violet `#8B5CF6` |
| Main text | `#F8FAFC` |
| Muted text | `#A7B0C0` |
| Light section background | `#F5F7FB` |
| Borders | `#273248` |

Use light and dark sections intentionally. A fully dark website can look attractive but may make long-form content and forms harder to read.

## 4.3 Typography

Suggested combination:
- Headings: Space Grotesk or a comparable modern geometric sans-serif.
- Body: Inter or a comparable highly readable sans-serif.

Typography rules:
- Strong, short headlines.
- Comfortable line length.
- Consistent heading scale.
- Clear paragraph spacing.
- Avoid excessive uppercase text.
- Do not use multiple unrelated font families.

## 4.4 Layout system

Recommended design tokens:

| Token | Specification |
|---|---|
| Main content width | 1,200–1,280 px |
| Wide content width | 1,360 px maximum |
| Desktop grid | 12 columns |
| Tablet grid | 8 columns |
| Mobile grid | 4 columns |
| Section spacing | 88–120 px desktop |
| Section spacing | 56–80 px tablet |
| Section spacing | 40–56 px mobile |
| Card radius | 12–20 px |
| Button height | 48–56 px |
| Body line height | 1.5–1.7 |

## 4.5 Buttons and interactions

Use three button styles:
- Primary: filled accent color.
- Secondary: outline or low-contrast surface.
- Text link: minimal, for supporting navigation.

Interaction rules:
- Clear hover and focus states.
- Visible keyboard focus.
- Consistent transitions.
- Avoid excessive scroll animations.
- Respect reduced-motion settings.

## 4.6 Imagery

Prioritize:
1. Actual product screenshots.
2. Real client work.
3. Approved team and workplace photography.
4. Custom illustrations.
5. Carefully selected stock imagery only when needed.

Avoid generic stock photos of people in meetings as the main visual proof of a technology company's capability.

# 5. Technical implementation specifications

## 5.1 Recommended implementation approach

If the existing website is built on a stable, maintainable stack, retain it unless a specific technical problem justifies migration.

For a new or substantially rebuilt implementation, a suitable modern stack would be:

| Layer | Suggested technology |
|---|---|
| Frontend | Next.js with React and TypeScript |
| Styling | Tailwind CSS or a consistent design-system approach |
| Content management | Headless CMS or an editor-friendly CMS |
| Forms | Validated server-side form handling |
| Database | PostgreSQL where persistent application data is required |
| Hosting | Managed platform or reliable cloud infrastructure |
| Analytics | Google Analytics 4 |
| Search reporting | Google Search Console |
| Lead management | CRM or a structured lead database |
| Error monitoring | Application error monitoring service |

The final technology decision should be based on the existing codebase, hosting, team capability and maintenance requirements.

## 5.2 Frontend requirements

- Responsive layout at mobile, tablet and desktop widths.
- Reusable components for navigation, cards, forms, CTAs and footers.
- Consistent design tokens.
- Semantic HTML.
- Accessible form labels and validation.
- Keyboard-accessible menus.
- Optimized images.
- Lazy-loading for below-the-fold media.
- No unnecessary animation libraries.
- No layout shifts from missing image dimensions.
- Custom 404 page.
- Useful loading and error states.

## 13.3 Persistent Lead Architecture & Production-Grade API Security

1. **Database & Repository Layer (`lib/database/leads-repository.ts` & `lib/database/schema.sql`)**:
   - Primary storage uses **PostgreSQL** (`leads` table with `id`, `lead_type`, `name`, `company`, `email`, `phone`, `country`, `details` JSONB, `source_url`, `utm_source`, `utm_medium`, `utm_campaign`, `status`, `consent`, `idempotency_key`, `created_at`).
   - Includes a clean Database Adapter pattern supporting PostgreSQL (`DATABASE_URL`) in staging/production with an automatic, logged development fallback so local verification and CI tests run reliably even before credentials are provisioned.
2. **API Hardening (`app/api/leads/route.ts` & `lib/security/`)**:
   - **Request Size & Content-Type Guard**: Reject payloads > 32 KB or non-JSON content types.
   - **Origin / CSRF Protection**: Verify `Origin` / `Referer` against allowed site hostnames.
   - **Trusted-Proxy Rate Limiting**: Redis/Upstash-compatible rate limiter (with in-memory sliding-window fallback) keyed by normalized IP + route.
   - **Idempotency & Deduplication**: Hash `(lead_type + normalized_email + normalized_phone + date_bucket)` to prevent duplicate double-submissions.
   - **International-Ready Validation (`lib/validations/leads.ts`)**: Normalize emails and support E.164 international phone numbers as well as local Bangladesh (`+880` / `01[3-9]`) formats, plus currency-neutral budget selectors (`USD` / `BDT`) and timezone-aware demo requests.
   - **Decoupled Notifications (`lib/crm/notifications.ts`)**: Fire webhook/email alerts asynchronously with error logging so notification latency never blocks the user's API response.
